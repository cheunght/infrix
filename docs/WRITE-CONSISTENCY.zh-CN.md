# Infrix 写入一致性与历史留存

资产、主数据、账号、系统配置及业务表单采用以下写入协议。外部调用方升级时需要同步新增请求头；成功响应结构继续保留原业务字段。

## 资产编辑

先读取 `GET /api/v1/assets/{id}/` 的 `revision`，再在 `PATCH` 或 `PUT` 中携带 `If-Match: "12"`，其中 12 是读取时的修订号。

服务器在事务中锁定资产后比较版本。版本不符返回 HTTP 409、`asset_revision_conflict` 和 `current_revision`，该次编辑不写入任何字段。缺少请求头返回 HTTP 428、`asset_revision_required`；无效格式返回 HTTP 400、`asset_revision_invalid`。客户端应重新读取、确认差异后提交，不能自动覆盖或重试旧表单。

资产普通写入及责任、报废、归档/恢复由[资产领域模块](ASSET-WRITES.zh-CN.md)负责，配置与审计在业务事务内提交。直接中心的新建与迁移在父锁内复核启用状态；批量逐条提交，范围外结果不披露资产号。前端保留打开时版本和独立草稿，迟到响应及跨表单确认不会覆盖新输入。

资产字段、配置、位置及责任关系变更会推进修订号。修订号可能一次增加多次，调用方只应比较相等。创建、导入和专用业务动作不要求 `If-Match`，仍按服务器当前状态和业务约束执行；这些动作也会使先前打开的资产编辑表单过期。

## 主数据编辑

以下 15 类记录的普通 PUT/PATCH 同样要求先读取记录的 `revision`，在提交中携带 `If-Match`：人员、部门、数据中心、机房、机柜、厂商、设备类型、资产型号、自定义字段、字段选项、字段集、标签、备件、备件类型、软件许可。

缺少请求头返回 428 / `resource_revision_required`，格式错误返回 400 / `resource_revision_invalid`，过期返回 409 / `resource_revision_conflict` 和当前版本。检查、修改与审计在同一事务内完成；机房和机柜遵守原有位置锁顺序。列表和详情中的版本都可用于编辑，但须保留打开表单时的版本，不能用后台新加载的列表版本替换。

字段集成员替换 `PUT /api/v1/custom-fieldsets/{id}/items/` 也要求该字段集的版本，并推进版本。导入更新会推进受影响记录的版本；创建不要求版本。前端保存及启停动作均使用所操作记录的版本，冲突保留输入，不自动覆盖。账号、系统配置、故障、维修、盘点和附件采用下述同类协议。

## 账号、配置及业务表单

下列普通编辑入口返回只读 `revision`；PUT/PATCH 必须携带打开表单时的 `If-Match`。缺少、格式错误和过期分别返回 428 / `resource_revision_required`、400 / `resource_revision_invalid`、409 / `resource_revision_conflict`。事务内重新读取并锁定记录，比较版本后再校验、修改及记录审计；冲突不写入字段、凭证或文件。

| 编辑入口 | 版本范围 |
| --- | --- |
| `/api/v1/users/{id}/` 与 `/api/v1/auth/me/` | 同一账号共享管理版本；管理员与本人资料不会互相覆盖 |
| `/api/v1/system/settings/` 与 `/api/v1/system/settings/branding/` | 共享系统设置版本；安全、SMTP、通知、常规和品牌配置互相使旧表单过期 |
| `/api/v1/auth/ldap/config/` | 独立目录配置版本；尚无数据库配置时 GET 返回 0，首次 PATCH 使用 `If-Match: "0"`，并发首次创建只允许一个成功 |
| `/api/v1/fault-events/{id}/`、`/api/v1/repair-records/{id}/` | 各自版本；沿用父故障锁、时间约束和资产状态同步 |
| `/api/v1/inventory-tasks/{id}/`、`/api/v1/inventory-items/{id}/` | 各自版本；沿用设施 → 资产 → 任务 → 盘点项锁顺序及观察验证 |
| `/api/v1/attachments/{id}/` | 备注和文件共用版本；先锁父资产，再锁附件，替换文件后旧备注表单不能写回旧文件引用 |

账号的名称、邮箱、启停、角色和密码变化推进管理版本，本人语言修改也推进该版本。顶部语言切换同样携带已读版本，成功后推进后续提交版本并保留个人资料草稿；较晚返回的保存结果不会覆盖新加载的资料。密码重置继续立即撤销全部有效 PAT；旧账号编辑表单同时失效。登录时间 `last_login` 不推进管理版本，正常登录不会使管理员表单过期。范围授权仍使用自己的授权版本和现有独占协调，不与账号资料版本混用。本人信息在同一次查询中读取资料与版本，避免给旧资料配上新版本。

账号批量启停 `POST /api/v1/users/batch-status/` 增加逐条版本映射，例如：

```json
{"ids":[12,15],"revisions":{"12":8,"15":3},"is_active":false}
```

每条在账号锁内比较版本并执行保护规则。缺少版本返回该条 `REVISION_REQUIRED`，过期返回 `REVISION_CONFLICT` 及 `current_revision`；其他条继续。保留 HTTP 200 和原逐条结果结构。客户端不能在确认期间重新读取最新版本替代选中时版本。

故障及维修写入由[维修领域模块](REPAIR-WRITES.zh-CN.md)维护事务、授权和审计。维修完成或重开同步更新故障状态、解决时间、修订号和更新时间。前端保留独立编辑快照，旧请求的响应不会关闭或覆盖新草稿。

创建不要求版本。盘点完成、重开、纠正和批量确认等专用动作按锁内当前状态与原观察规则执行；完成或重开会使任务旧表单过期。备件及维修用件沿用下一节的幂等协议。密码动作不保存明文重放结果，配置与审计只返回凭证已配置状态，不返回明文。LDAP 省略密码时保留锁内当前密文。

浏览器保留打开表单时的版本副本，收到冲突保留名称、备注、费用、配置和待提交密码等输入，提示重新读取后确认，不自动重试写请求。私有品牌配置返回版本，公开品牌展示接口保持原结构。

## 软件实际使用

`used_count` 表示录入的实际使用数，可以超过 `authorized_count`；两者仍须为非负整数。超授权记录保留在列表、导出、到期状态筛选及总量统计中，并产生超授权告警。到期状态仍为正常、即将到期、已过期，与是否超授权分别判断。

例如授权 5、实际使用 8：剩余数为 -3，使用率为 160%，界面显示超授权 3。授权 0、实际使用大于 0 时，使用率返回 null，界面提示无授权额度且存在实际使用；两者均为 0 时使用率为 0。这是实际消费录入和告警修正，尚未增加设备授权分配或自动授权对账。

## 备件与维修用件

以下 POST 请求必须携带 `Idempotency-Key`：

- `/api/v1/spare-transactions/`
- `/api/v1/fault-events/{id}/part-usages/`

每次新的逻辑操作生成一个不同的键；网络中断、超时或响应读取失败后重试原操作时，复用同一个键和请求内容。键允许 1–128 个可见 ASCII 字符。缺少键返回 HTTP 428、`idempotency_key_required`；格式错误返回 HTTP 400、`idempotency_key_invalid`。

同一用户、同一路径、同一键及相同 JSON 内容返回原成功状态和响应，并附带 `Idempotency-Replayed: true`；JSON 属性顺序不影响判断。同一键配不同内容返回 HTTP 409、`idempotency_conflict`。不同用户和不同路径各自独立。鉴权与当前权限仍需通过。

业务写入、审计和幂等结果在同一事务提交。数据库唯一约束协调并发重试；失败全部回滚，重试可以重新执行。键和请求内容只保存摘要，成功响应保留在数据库，随备份恢复。当前不自动到期或清理结果；完全重置系统会删除这些记录。

浏览器在收到并读完确定结果之前，保留未确认操作的键；网络错误、5xx 和维护响应不自动重试写请求。收到成功结果后，相同内容的下一次新操作使用新键。

库存写入已由[库存领域模块](STOCK-WRITES.zh-CN.md)统一负责。内部领料的同键重放也重新检查当前库存功能能力与范围；撤销能力后返回 403。余额、流水、用件、审计及幂等结果同事务提交，审计失败也整体回滚。

## 归档与恢复

单条 DELETE 和 `batch-delete` 路径保留，行为改为归档；单条成功仍为 204，批量成功结构不变。界面改为“归档资产”。存在当前使用人、机柜 U 位、未关闭故障、未完成维修或进行中盘点时阻止归档，错误码为 `asset_archive_blocked`。

归档保存资产详情和操作者快照，保留报废、维修、使用人、盘点及附件记录。资产编号与序列号仍被占用，不能重新用于另一个资产。网络地址配置也保留并继续参与地址唯一性校验；需要复用地址时，应先清理再归档，或恢复归档资产后清理地址。默认台账、统计、业务选择和新盘点范围排除归档资产；`GET /api/v1/assets/?archived=true` 及详情、历史路径的同名参数可查询归档记录，包括 `/api/v1/assets/{id}/inventory-records/?archived=true`。归档列表、详情和导出使用冻结的字典、标签及数据中心名称；关联主数据仍保留引用，不能因资产归档而删除。

归档资产的普通编辑及历史维修、附件修改入口关闭，历史和附件仍可查看、下载。附件写入在父资产锁内重新读取当前文件引用，避免备注编辑写回已替换的旧文件。Admin 继续只读，可查看归档资产。`POST /api/v1/assets/{id}/restore/` 恢复同一个资产，保留原业务状态；恢复已报废资产不会取消报废。写入与归档竞争时，锁内再检查当前状态，已归档返回 `asset_archived`。

完全重置系统是原有的独立清空操作，仍会删除归档和历史资料，不用于日常归档。

## 盘点历史

实际位置保存 `actual_location_snapshot`，列表、详情和导出使用记录时的名称。正常结果确认任务创建时的系统位置；修改备注不重写位置快照，重置为未盘点时清空该次观察。盘点资产编号、名称、设备类型和序列号优先使用任务快照。

旧的已盘点记录按升级时仍存在的实际位置回填，来源标为 `legacy_backfill`；升级前已被改写的名称无法还原。纠正动作仍使用真实位置引用和当前约束，不能仅凭历史名称修改台账。

盘点项新增 `actual_placement` 和 `actual_data_center_id`：

- `mounted`：必须有实际机柜及完整 U 位；数据中心从机柜归属确定。
- `data_center`：必须选择实际数据中心，机柜及 U 位为空；纠正会移除机柜占用并设置直接归属。
- `unlocated`：数据中心、机柜及 U 位均为空；纠正会清空资产位置。
- 空字符串：位置尚未确认，允许记录异常，但不能执行位置纠正。旧记录缺少证据时保持此状态，不推定为清空位置。

正常结果由服务器从任务快照确定位置；未盘点或未找到会清空本次观察。修改备注不重写观察名称。机柜在观察后改挂机房或数据中心，按旧观察纠正返回 409 / `inventory_observation_stale`；等待锁期间观察被修改则返回 409 / `inventory_observation_changed`。重新记录现场位置后才能继续纠正。名称单独改变不会改变地点身份。导出新增末尾“实际位置类型”列。

## 安装与升级

前三批迁移为 `0003`–`0005`；第四批新增 `0006`–`0008`，移除实际使用不得超授权的约束，补盘点位置类型/数据中心引用，并为 15 类主数据增加修订号。盘点迁移保留已有冻结名称和来源，不推定旧的不明确位置；旧主数据版本初始为 1。阶段 1 新增 `0009`–`0012` 的范围授权与归属字段；阶段 2A 新增 `0013`，仅为上述七类业务/配置记录增加 revision，并为账号安全资料增加 administration_revision，已有记录初始值均为 1。该迁移不重写业务字段、历史快照、文件路径或加密凭证。安装流程已有迁移步骤。手工升级时，停止动态服务并按现有部署说明执行 `python manage.py migrate` 后，再开放新版前后端；外部客户端同步更新请求头，避免旧客户端和新写入协议混用。

新增记录纳入现有服务器 CLI 备份恢复。恢复前仍须检查迁移兼容性；旧格式指归档格式兼容，不表示任意旧数据库结构可以直接导入新版服务。现有开发业务库不会自动迁移或清理数据。

盘点规则与提交入口由[盘点领域模块](INVENTORY-WRITES.zh-CN.md)统一维护。任务写入锁定位置及固定清单后复核授权，单条与批量正常确认共用快照校验；直接位置的数据中心也必须存在且启用。观察、纠正及逐条批量事务保留原协议。
