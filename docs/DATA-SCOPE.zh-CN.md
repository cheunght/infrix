# 数据中心范围授权

功能角色决定账号能做什么，数据范围决定它能对哪些记录执行操作。两者同时满足才能访问。数据中心范围通过主应用「组织管理 → 用户 → 数据范围授权」配置，仅系统管理员可修改，修改会产生审计记录。

## 默认与授权规则

- 系统管理员角色及超级用户拥有全局范围。`is_staff` 本身不授予全局访问或 Admin 访问。
- 其他新账号和升级前的普通账号默认没有业务数据范围；迁移不会自动赋予全局权限。部署后由管理员按实际职责逐个配置。
- 读、写中心集合分别配置，多中心授权取并集；写授权包含同范围读取。
- 未上架但直接归属中心的资产按该中心判断。已上架资产按机柜所属中心判断。没有任何位置归属的资产需要显式「待归属」授权；清除资产中心归属也需要待归属写权限。
- 全局读/写授权是独立的管理选项，不能仅根据资产管理员或审计员角色推导。
- 资产迁移、机房/机柜改挂、备件调拨同时检查来源和目标。位置变更在现有业务锁内重新校验；此前列表可见不保证随后仍可写入。
- Session 和 PAT 使用同一范围。授权更改在单机的独立维护目录中取得账号独占锁，等待已进入的请求及流式下载结束后提交；提交后新请求按新范围判断。锁文件保持原位，由多个 Gunicorn worker 共用。

## 资源处理矩阵

| 资源/入口 | 当前规则 |
| --- | --- |
| 资产列表、详情、轻量选择、资产导出 | 按资产当前中心或待归属授权过滤；归档资产同样判断 |
| 资产分配历史、相关故障与维修、附件下载 | 继承关联资产范围；写入另需对应功能能力及写范围 |
| 数据中心、机房、机柜、备件余额 | 按所属中心过滤；选择项和写入关联对象同步限制 |
| 库存流水 | 来源与目标均可读才返回；调拨写入须两端可写 |
| 维修用件 | 资产与内部库存来源同时授权；幂等重放重新验证来源 |
| 盘点任务与明细、结果导出及资产盘点历史 | 仅完整任务可见。任务中心、所有资产当前位置、冻结原位置及已填写观察位置均需授权；未知旧快照只向全局账号开放 |
| 全部资产盘点 | 需要全局写范围 |
| 备件、许可、型号、厂商、字段、标签、人员与部门 | 公司共有参考资料，读取沿用对应功能能力；修改需要全局写范围。人员/字典的跨中心资产统计向局部账号返回空值 |
| 备件全局数量、安全库存判断 | 保持全局口径；局部账号需另授「全局库存指标」权限才能读取，否则全局数量、地点数、低库存标记和全局流水存在标记返回 `null`，页面显示「无权限」 |
| 备件详情的位置余额及最近流水 | 只返回可读位置和两端均可读的流水；位置筛选同时受授权约束 |
| Admin | 仅系统管理员可进入，业务记录继续只读；不能用普通 staff 账号旁路查询 |

本批没有重新划分资产的部门归属。公司共有人员、部门和许可资料在当前功能能力下可读；这不表示拥有这些人员使用的所有资产。

## 暂时需要全局授权的入口

范围内报表投影和批量导入将在后续批次继续适配。目前仪表盘、告警汇总、设施汇总、机柜布局导出、备件汇总导出、型号导出、各类导入、系统设置及批量业务动作需要相应全局读/写范围。完整资产审计时间线同样需要全局读取，防止其中库存变化及跨中心观察透露范围外信息。原始操作日志与通知投递日志只向全局读取账号开放。

这些入口向局部授权账号返回明确拒绝，不自动扩大范围。范围内资产导出、维修导出、库存流水导出、盘点结果导出已可使用。后续 1C 批次将提供局部汇总、逐条批量结果和对应页面行为；不能把当前的拒绝当作已完成这些功能。

## 授权 API

`GET /api/v1/users/{id}/data-scope/` 返回保存的授权、修订号、中心选项和有效授权。尚未配置时修订号为 `0`，有效授权仍按角色和默认规则判断。

`PUT /api/v1/users/{id}/data-scope/` 全量替换保存授权，须提供读取时的 `If-Match`，如 `"0"` 或 `"3"`。省略的布尔值为 false、中心集合为空，不保留旧授权。字段：

- `read_data_centers`、`write_data_centers`：中心 ID 数组。
- `global_read`、`global_write`：全局授权。
- `unlocated_read`、`unlocated_write`：待归属资产授权。
- `global_stock_metrics`：全局库存指标授权。

缺少有效版本返回 428 `data_scope_revision_required`；版本冲突返回 409 `data_scope_revision_conflict`。对象列表及详情将越界对象视作不可见；越界关联字段返回 400，锁内权限变化或未经授权的全局入口返回 403 `data_scope_denied` / `data_scope_global_required`。

## 升级与运维边界

应用 `0009_user_data_scope` 迁移后，先使用原系统管理员登录并为普通账号授权，再开放普通用户使用。先核对实际中心归属；未归属记录留给明确待归属授权或全局管理员，不能批量猜测位置。

服务器命令保留运维账号的独立权限边界。备份恢复仍使用 CLI 和独占维护窗口；授权表、中心授权关系及授权修订号随数据库备份恢复。恢复成功后会话失效，重新登录后使用恢复后的授权。

当前协调范围为单机多 worker。多个节点不能共享此处的本机文件锁，需要先完成分布式授权变更和维护协调设计。
