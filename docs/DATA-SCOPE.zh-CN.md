# 中心与部门范围授权

功能角色决定账号能做什么，数据范围决定它能对哪些记录执行操作。两者同时满足才能访问。范围通过主应用「组织管理 → 用户 → 数据范围授权」配置，仅系统管理员可修改，修改会产生审计记录。

## 默认与授权规则

- 系统管理员角色及超级用户拥有全局范围。`is_staff` 本身不授予全局访问或 Admin 访问。
- 其他新账号和升级前的普通账号默认没有业务数据范围；迁移不会自动赋予全局权限。部署后由管理员按实际职责逐个配置。
- 每个账号保留一条基础规则，可追加最多 20 条规则并命名。各规则独立配置读、写中心与部门集合；资产必须在同一条完整规则内同时符合中心和归属部门，规则之间取并集。写授权包含这一完整写范围的读取，不把读、写条件拆开重新组合。人员目录按各规则的部门集合并集判断。
- 资产 `owning_department` 是独立归属字段，指定、转交、归还使用人和位置迁移均不自动改变它。改变归属要同时拥有来源、目标部门的写范围；从空归属分配和清空归属分别需要待确认归属写授权。
- 选中部门按 ID 精确匹配，不自动包含下级。`all_departments_read/write` 覆盖所有已归属部门；空部门还需 `unowned_read/write`，不会因选择“所有部门”而自动开放。
- 例如基础规则为 `(A,D1)`、附加规则为 `(B,D2)`，只开放这两种组合，不开放 `(A,D2)`、`(B,D1)`。同一规则选择 A/B 中心和 D1/D2 部门仍会开放四种组合；仅需两个组合时应分别配置规则。读规则 `(A,D1)` 与写规则 `(B,D2)` 也只允许读取这两种完整组合。
- 未上架但直接归属中心的资产按该中心判断。已上架资产按机柜所属中心判断。没有任何位置归属的资产需要显式「未指定位置」授权；清除资产中心归属也需要未指定位置写权限。未指定位置与未确认部门归属分别授权。
- 全局读/写及全局库存指标是账号级选项，不配置在附加规则内。全局授权优先于规则；不能仅根据资产管理员或审计员角色推导。
- 资产迁移同时检查来源和最终目标的完整组合。一次提交可把 `(A,D1)` 同时改为 `(B,D2)`，前提是两端均可写；锁内完成全部更新，任何失败整笔回滚。单独改变其中一个字段、留下未授权的交叉组合会被拒绝。机房/机柜改挂逐项检查所有关联资产的来源与目标组合；此前列表可见不保证随后仍可写入。备件调拨按两端中心检查。
- Session 和 PAT 使用同一范围。授权更改在单机的独立维护目录中取得账号独占锁，等待已进入的请求及流式下载结束后提交；提交后新请求按新范围判断。锁文件保持原位，由多个 Gunicorn worker 共用。GET/HEAD 请求在账号准入后使用一致数据库快照完成查询及响应组装，防止并发改挂导致旧中心标签与新中心资产混合返回；普通写请求继续使用原有隔离级别。流式文件在响应准备后关闭数据库快照，账号锁仍保持到下载结束。

## 资源处理矩阵

| 资源/入口 | 当前规则 |
| --- | --- |
| 资产列表、详情、轻量选择、资产导出 | 按当前中心/未指定位置与归属部门/待确认归属同时过滤；归档资产同样判断 |
| 资产分配历史、相关故障与维修、附件下载 | 继承关联资产的中心与部门范围；写入另需对应功能能力及写范围。指定/转交的目标人员必须在人员可读部门内，锁内重新检查 |
| 数据中心、机房、机柜、备件余额 | 按所属中心过滤；设施修改还需完整关联资产的写范围，在位置锁内复核，不能顺带修改其他部门的资产位置 |
| 库存流水 | 来源与目标均可读才返回；调拨写入须两端可写 |
| 维修用件 | 资产与内部库存来源同时授权；幂等重放重新验证来源 |
| 盘点任务与明细、结果导出及资产盘点历史 | 仅完整任务可见。任务中心、所有资产当前中心/归属部门、冻结原中心/归属部门及已填写观察位置均需授权。原始与新观察快照均冻结当时归属部门 ID；缺少旧部门证据时需在该快照中心拥有完整部门范围，位置证据仍须通过。旧观察不根据资产当前部门回填。预览与创建要求整个范围可写；资产详情及归档快照中的盘点摘要也按完整任务过滤 |
| 全部资产盘点 | 需要全局写范围 |
| 备件、许可、型号、厂商、字段与标签 | 公司共有参考资料，读取沿用对应功能能力；修改需要全局写范围。字典的跨范围资产统计向局部账号返回空值 |
| 人员与部门 | 人员及选择项按人员部门过滤，部门列表按授权部门过滤；人员与组织主数据修改仍需全局管理授权。组织父级标签只是路径信息，不授予父级数据范围 |
| 备件全局数量、安全库存判断 | 保持全局口径；局部账号需另授「全局库存指标」权限才能读取，否则全局数量、地点数、低库存标记和全局流水存在标记返回 `null`，页面显示「无权限」 |
| 备件详情的位置余额及最近流水 | 只返回可读位置和两端均可读的流水；位置筛选同时受授权约束 |
| 仪表盘、设施汇总、机柜布局导出 | 资产指标先按中心与部门筛选。在对应中心缺少完整部门读取边界时，完整占用量、可用 U、设备数及利用率为 `null`，返回 `capacity_restricted/occupancy_restricted`；页面显示无权限并关闭完整 U 图，机柜导出占用单元格也显示无权限。跨中心汇总继续保守检查整个读取范围；只有目录全部门授权不能开放资产占用指标。授权内设备可从台账及机柜设备子集读取 |
| 告警汇总 | 维保、故障按资产范围，盘点按完整任务范围；公司许可沿用许可功能权限；无全局库存指标授权时省略低库存告警及计数 |
| 备件汇总导出 | 位置筛选受读范围限制；数量与地点数保持全局口径，无指标授权时导出「无权限」 |
| 批量归档、指定/转交、编辑 | 每项独立校验写范围，在物理位置锁内复核来源与目标；范围外与不存在记录返回通用失败，不披露编号或名称；授权内项目继续处理 |
| 批量盘点确认与异常处理 | 只处理完整可写任务中的明细；越界/不存在明细逐项失败且不披露资产信息。授权内明细仍须来自同一任务 |
| 资产导入模板、预览与确认 | 模板沿用导入功能能力；预览和确认使用当前写范围解析部门与位置，使用人只从可读目录匹配。新增 `owning_department` 列，不推断归属。任意异常行阻止整批提交，确认重新校验，不把预览结果当作授权凭证；临时事务冲突返回 409 和最新预览，确认写入不自动重放 |
| 型号导出 | 共享目录读取，沿用系统设置功能权限及现有筛选，不需要全局数据读取，不导出关联资产或跨范围统计 |
| 资产时间线 | 当前资产须可读。事件时间、类型和操作人保留；历史明细需当时的冻结范围证据。新相关审计保存中心、部门与库存来源证据；资产变更的前后快照均需可读。盘点另需完整任务可见，库存另需来源、目标均可读；证据不足或越界时隐藏明细，返回 `metadata.scope_restricted=true` |
| Admin | 仅系统管理员可进入，业务记录继续只读；不能用普通 staff 账号旁路查询 |

资产可能由范围外人员使用。此时详情、列表和导出保留绑定 ID，人员名称显示「无权限」，员工编号、部门、联系方式等目录资料不展示；`directory_restricted` 标明限制，不自动清除使用关系。自助账号资料仍可读取本人信息。

责任事件的旧部门仅有名称，不能据此授权。缺少完整部门读取边界时，历史人员识别资料统一不展示；操作类型、操作人及业务原因仍作为已授权资产的事实保留。资产时间线中的人员也依据冻结部门信息脱敏；旧人员快照没有部门 ID 时，缺少完整部门读取边界的账号只能看到受限提示。位置冲突涉及越界设备时返回通用不可用提示，不带该设备编号或占用范围。

## 暂时需要全局授权的入口

型号、人员和部门导入修改共享主数据，仍需全局写范围；系统设置沿用对应全局读/写授权。原始操作日志与通知投递日志只向全局读取账号开放。资产导入、型号导出和资产时间线已适配局部账号，不自动扩大账号范围。

同一资产变更事件的任一侧历史范围越界时，整条事件明细隐藏。时间线受限事件仍计入分页总数，不删去事件制造完整历史的假象；明细和关联 ID 会隐藏，界面明确说明限制。该视图是业务事件投影，不是原始审计日志下载。现有历史审计不回填范围证据、不改写原记录；历史证据同样按完整规则并集判断，不能跨规则拼接中心与部门。

## 授权 API

`GET /api/v1/users/{id}/data-scope/` 返回保存的授权、修订号、中心/部门选项和有效授权。尚未配置时修订号为 `0`，有效授权仍按角色和默认规则判断。

`PUT /api/v1/users/{id}/data-scope/` 全量替换保存授权，须提供读取时的 `If-Match`，如 `"0"` 或 `"3"`。省略的布尔值为 false、中心/部门集合为空，不保留旧授权。字段：

- `read_data_centers`、`write_data_centers`：中心 ID 数组。
- `global_read`、`global_write`：全局授权。
- `unlocated_read`、`unlocated_write`：未指定物理位置的资产授权。
- `read_departments`、`write_departments`：部门 ID 数组，精确匹配。
- `all_departments_read`、`all_departments_write`：所有已归属部门的授权。
- `unowned_read`、`unowned_write`：未确认部门归属的资产及无部门人员授权。
- `global_stock_metrics`：全局库存指标授权。
- `rules`：最多 20 条附加规则，数组顺序作为显示顺序。每条包含可选 `name`（最多 80 字）及上述中心、部门、未指定位置、所有部门、待确认归属字段；缺省集合为空、布尔值为 false。规则内禁止账号级 `global_read/global_write/global_stock_metrics`。GET 返回只读规则 ID；PUT 不依赖原 ID，以整个数组替换。

省略 `rules` 等同于空数组，会清除已有附加规则；旧客户端应先升级再维护已有多规则账号。基础规则和附加规则共用一个修订号，替换在同一事务及账号独占锁内完成，并审计变更前后授权。有效授权中的平铺中心/部门用于中心设施与人员目录选择；资产判断使用 `rules` 中的完整条件，不能自行对平铺集合做笛卡尔积。

缺少有效版本返回 428 `data_scope_revision_required`；版本冲突返回 409 `data_scope_revision_conflict`。对象列表及详情将越界对象视作不可见；批量业务动作保留成功响应结构，范围外 ID 与不存在 ID 均返回逐项通用失败，整批请求可为 HTTP 200，应检查 `succeeded`、`failed` 和 `results`；越界关联字段返回 400，锁内权限变化或未经授权的全局入口返回 403 `data_scope_denied` / `data_scope_global_required`。

关联选择可用 `scope_access=write` 请求写范围子集，不能扩大读范围。资产接口新增 `owning_department` 与只读 `owning_department_name`，普通修改沿用原 `If-Match`；导入 `owning_department` 接受启用部门名称或编码，缺省仍为空，空归属必须显式授权；资产导出增加归属部门列，使用人部门列继续表示人员资料。

## 归属确认与升级

部门归属迁移为 `0010_asset_ownership`、`0011_department_data_scope`；多规则迁移为 `0012_data_scope_rules`。0012 仅新增附加规则及关联表，现有授权保留为基础规则，不自动生成附加规则、不改变修订号，也不回填旧快照。读、写组合分别判定会收紧原先把两类条件混合后产生的交叉读取；确有业务需要的组合须明确授权。现有资产归属保持 `null`，现有中心授权保留，新增部门范围及待确认归属授权默认为关闭；不从使用人部门推导、不自动扩大旧账号范围。升级后先由系统管理员核实归属、补齐授权，再开放普通账号。

服务器运维账号可生成只读 JSONL 预览：

```bash
python manage.py preview_asset_ownership --only-unowned > ownership-preview.jsonl
```

预览包含资产 ID、当前中心、当前归属、是否归档以及使用人部门候选。候选仅供人工核实；命令没有应用或自动回填选项，不改动业务数据及授权。确认后通过主应用逐项设置归属，并保留版本冲突检查；归档记录先安排独立确认处理，不借升级改写历史快照。

## 运维边界

应用 `0009_user_data_scope` 迁移后，先使用原系统管理员登录并为普通账号授权，再开放普通用户使用。先核对实际中心与部门归属；未确认记录留给明确相应授权或全局管理员，不能批量猜测位置或部门。

资产预览仍采用试写后回滚以复用业务约束；MariaDB 下同一数据库的预览逐行取得连接级命名锁，结束或连接退出即释放，正式提交不取得该锁。临时死锁只允许在独立预览事务完整回滚后有限重试；确认提交发生冲突时整批回滚并返回 409。大文件导入仍为同步，后台作业留给后续阶段。

服务器命令保留运维账号的独立权限边界。备份恢复仍使用 CLI 和独占维护窗口；资产归属、授权表、基础和附加规则、中心/部门授权关系及授权修订号随数据库备份恢复。恢复成功后会话失效，重新登录后使用恢复后的授权。

当前协调范围为单机多 worker。多个节点不能共享此处的本机文件锁，需要先完成分布式授权变更和维护协调设计。
