# 资产领域写入

普通创建与编辑、领用/转交/归还、报废及归档/恢复由 `backend/assets/asset_writes.py` 负责。`asset_write_rules.py` 管理字段解析后的业务校验和部分位置合并，`asset_configuration.py` 管理网络、采购/维保、自定义值及标签存储，`asset_batches.py` 管理逐条批量事务与结果。物理位置锁和变更仍复用 `physical_location`，维修状态继续由维修模块维护。

视图保留字段解析、查询与响应投影，序列化器委托同一份规则及写入实现。`services.py` 保留原配置、责任、报废、库存、盘点和维修函数的兼容导出。未新增业务字段或迁移，现有成功响应结构和导入规则保留。

## 写入、位置与授权

普通资产编辑在资产锁内比较 `revision` / `If-Match`。能够更改或清除位置的配置写入，先锁来源和目标位置父级，再锁资产；纯元数据编辑保持资产行锁。新建资产先锁位置父级，再插入资产，避免外键共享锁与后续独占位置锁交叉。

直接归属数据中心的新建和迁移在取得父锁后重新读取中心启用状态；等待期间目标中心被停用，返回字段错误 400，不写入资产、配置、版本或成功审计。已有资产仍可保留原停用中心；上架位置继续校验中心、机房、机柜、U 位和启用状态。部分配置沿用原合并规则，显式下架与清空位置仍有不同含义。

功能能力与数据范围分别检查。普通 HTTP 编辑及生命周期动作需要当前 `assets.manage`；当前资产、目标位置和归属组合在锁内复核，人员选择按其部门权限检查。归档与恢复也复用位置和资产锁。归属部门独立于当前使用人，领用、转交及位置变化不自动改写归属。

普通创建/编辑由领域写入记录包含配置和自定义值变化的审计，更新的前值在锁内读取。导入与批量事务保留各自的来源及批次审计，不增加重复的普通编辑审计；字段序列化器的内部上下文选择审计归属，该标志不作为客户端字段开放。HTTP 准入持续覆盖事务及提交后文件回调；可信旧调用和未来作业仍须明确维护、账号授权与审计准入。

## 生命周期及批量操作

领用、转交、归还保留原状态规则，责任事件冻结人员和操作者信息。维修状态由故障/维修流程维护，普通编辑或责任操作不能绕过；报废经专用动作写入处置事实，已报废状态保持终态。

归档仍要求没有当前使用人、机柜占用、未关闭故障、未完成维修或进行中盘点，保留原编号、快照、业务历史及附件。恢复返回同一资产，不取消报废，不重建或清除历史。旧已报废资产没有处置事实时继续显示为历史记录，不猜测原因。

批量编辑、责任变更和归档逐条独立提交，使用锁内当前状态，不新增版本或幂等请求字段。某条记录发生范围拒绝、约束失败或审计存储错误时，该条回滚，其余记录可以成功；范围外失败结果只使用提交的 ID，不泄露资产号。任何单条动作的配置、状态、事件与审计一起提交或回滚。

## 前端

`useAssetLifecycle` 管理责任、报废、归档/恢复及批量操作，`useAssets` 保留页面接口、详情和编辑表单。成功后刷新原目标的详情及相关历史；刷新失败明确提示，不自动重试写入。

资产表单每次打开使用独立的请求序号。旧保存的成功或错误不清空、关闭或污染新打开的草稿；清除折旧或舍弃自定义值的确认期间切换表单，会取消该提交/重提。批量责任操作只移除成功提交的资产选择，保留失败项和请求期间新增的选择。
