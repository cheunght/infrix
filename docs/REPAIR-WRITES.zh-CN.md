# 故障与维修领域写入

故障和维修的创建、普通编辑、删除、完成及重开由 `backend/assets/repair_writes.py` 负责。视图保留原 API 路径和响应，序列化器解析字段并调用同一组业务校验。`services.py` 保留原生命周期函数的兼容导出。维修领料及其库存、流水和幂等结果仍由库存模块负责。

## 状态、时间与历史

故障的关闭状态和解决时间只由维修完成时间派生。完成和重开同时推进故障修订号及 `updated_at`，旧编辑表单继续返回版本冲突。维修开始、完成和报障不得早于故障发生；完成不得早于开始；允许先维修、后补报障，开始时间未知时也检查完成时间。

同一资产存在任意未关闭故障时，资产保持维修状态。最后一条故障关闭后，按原先保存的维修前状态恢复；缺少有效快照时不猜测历史状态。已报废资产不能新建或重开未关闭故障，已归档资产的历史维修不能修改。

已关闭故障和已完成维修不能普通编辑或删除。阶段 3A 后，重开从最近已完成轮次新增空白轮次，原 ID、时间、服务商、费用、备注、用件和附件保持不变。故障关闭状态只取最近轮次；同一故障的旧轮次保持只读。后续轮次的开始或完成时间不能早于前轮完成时间；修改故障发生时间时检查全部保留轮次。

存在任何维修轮次的故障不能删除。只有没有前轮、用件和附件的未完成第一轮可删除；后续轮次与已完成轮次持续保留。已完成轮次的附件可查看和下载，禁止新增、替换、编辑和删除。迁移、接口和页面规则见[多轮维修](REPAIR-ROUNDS.zh-CN.md)。

## 事务与授权

维修写入按父故障 → 维修记录 → 资产取得行锁；故障创建先锁定父资产。维修用件仍先取得库存及位置父锁，再取得故障、维修和资产锁，与库存模块保持一致。创建、重开及首次领料建轮在父故障锁内重新校验当前轮次和时间规则，普通编辑在锁内比较 `If-Match`，避免并发完成后继续编辑历史记录。等待锁期间故障或维修被删除时返回 404，提示刷新，不将缺失记录作为服务器异常。

领域写入重新检查当前 `faults.manage` 及对象写入范围，资产状态同步时锁定并复核当前资产。业务记录、派生故障状态、资产快照及审计在同一事务内提交，任何一步失败全部回滚。审计继续使用现有资源类型、来源及前后值，不增加凭证原文。

HTTP、后台作业沿用维护、认证及账号授权准入，访问锁覆盖事务提交和文件回调。维修附件按父故障 → 维修 → 资产取得锁，与完成、重开和领料串行。兼容函数的服务器调用属于可信内部入口，不能把兼容导出当作独立授权入口。阶段 3A 新增迁移 0015。

## 前端编辑

`useRepairs` 保留页面接口，维修编辑快照、保存和重开由 `useRepairLifecycle` 管理。每次打开表单生成独立快照；另一故障或同一故障的新草稿不受旧请求迟到成功或错误影响。保存提示依据提交时的表单生成，版本冲突保留输入；写入失败不自动重试。

重开确认前固定目标；确认期间切换编辑器取消提交。请求已经发出后切换编辑器，服务器结果仍对应原目标，迟到响应不关闭新的表单。成功后刷新故障列表和原资产详情。
