# 盘点领域写入

`backend/assets/inventory_writes.py` 维护盘点任务、现场观察、异常纠正、批量确认及任务完成/重开的规则和写入。原范围查询仍在 `inventory.py`；视图解析 HTTP 请求，序列化器处理字段并使用同一份领域校验。原 `assets.services` 的盘点函数保留兼容导出。

## 提交入口

| 入口 | 行为 |
| --- | --- |
| `create_inventory_task` | 校验范围与上限，锁定候选资产，生成固定清单和原始快照，同事务写审计 |
| `update_inventory_task` / `delete_inventory_task` | 在锁内重查完整范围、版本和生命周期；只允许删除尚未开始且没有处理记录的任务 |
| `record_inventory_observation` | 校验读取版本和当前任务状态，记录现场观察、操作人和检查时间，按既有规则重置异常处理状态 |
| `confirm_inventory_item_normal` | 从任务创建时的快照确认正常，单条与批量共用位置规则 |
| `resolve_inventory_item` | 锁内核对最新观察、处理状态与当前权限，记录处理；纠正台账与两类审计共同提交 |
| `submit_inventory_batch` | 批量确认正常或处理异常；每条独立提交，保留成功/失败结构，范围外记录不返回资产身份 |
| `change_inventory_task_status` | 完成前检查未盘点项，重开前检查归档资产，推进任务版本并记录审计 |

已有 HTTP 路径、请求字段和成功结构保留。普通任务/观察编辑沿用 `revision` / `If-Match`；状态动作及批量按锁内当前状态执行，不新增幂等凭据或要求外部客户端提交新字段。批量更新资产台账仍不支持，位置纠正须逐条执行。

## 位置与授权

任务编辑、删除、完成及重开按任务的数据中心/机房 → 固定清单资产（按主键）→ 任务 → 必要盘点项取锁，锁内重新检查完整任务授权。观察与纠正继续按物理位置图 → 资产 → 任务 → 盘点项取锁，保持与设施变更的顺序一致。新任务在父位置锁内重新检查启用状态和机房归属，资产清单及原始快照一旦生成不随之后移动重建。

盘点写入需要当前 `inventory.manage` 和完整任务数据范围；更新资产台账还需要 `assets.manage`。当前资产位置/归属、原始快照、现场观察各自满足范围，不能用一个可见项代表完整任务授权。批量中的不可访问记录只返回所提交的盘点项 ID、失败标志和原因。

正常确认使用原始快照。机柜位置继续校验原中心、机房、机柜身份、启用状态及 U 位；直接归属数据中心的快照也校验中心存在且启用。停用或缺失时，单条确认失败，批量返回该项失败；不会写入正常结果、检查时间或成功审计。没有地点的快照仍允许明确记录为未指定位置。

现场观察继续冻结位置名称、U 位及记录时资产归属；后来重命名或移动设施不重写历史。已完成任务锁定盘点结果录入，但仍允许处理待解决异常；处理拒绝已解决异常、已归档资产，以及记录后改变了机房/中心归属的实际机柜。审计失败时，任务及清单、观察，或者纠正后的资产和处理结果一起回滚。

## 前端与运行约束

`useInventory` 保留页面接口，任务完成/重开交给 `useInventoryTaskActions`。完成确认前固定任务 ID；确认期间切换任务就取消该提交，迟到响应也不替换当前查看的任务。观察表单继续保留打开时版本和输入，写入错误不自动重试。

本批没有新增迁移，开发业务库不自动迁移。HTTP 入口沿用现有维护、认证及账号授权准入；以后作业或服务器内部调用仍须显式持有同样的准入锁，覆盖事务和提交后的回调。兼容导出不能替代后台作业准入。当前备份恢复继续使用服务器 CLI 和单机多 worker 维护屏障。
