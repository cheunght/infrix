## 2. 阶段 0：工程与运行基线

**实施范围**

1. 确定目标 Python、MariaDB、Node 运行版本，锁定后端依赖及安装来源，保留前端锁文件，形成可重复构建方式。
2. 建立私有自动验证入口与执行环境。测试不纳入 Git，因此需要保存与产品提交对应的私有验证包版本或校验摘要，执行环境明确挂载 `ITAM-private`；不能假设只克隆产品仓库即可运行全部验证。
3. 准备目标服务器上的独立验收库，确认 HTTPS、可信代理、服务账号、媒体及备份目录、独立维护目录、日志和容量配置。
4. 核实 LDAP、邮件与 2FA 的目标配置，整理故障定位入口、备份保留策略及离线副本安排。恢复目标和可接受停机窗口由运维与业务明确。
5. 整理安装、升级、失败恢复及回退步骤。首次安装应用全部迁移；已有环境升级执行 `migrate`，覆盖当前新增的 `0003–0014`。外部客户端同步采用新请求头。

**完成标准**：同一提交能在干净环境安装和构建；依赖可追溯；目标验收环境能够完成数据及附件恢复、重新登录和正常业务操作；发布记录明确版本、配置、执行人和恢复方式。涉及数据结构改变的回退须恢复匹配的数据及媒体，不能只替换旧代码。

**交付物**：运行版本矩阵、依赖锁定文件、发布与恢复操作说明；私有自动验证配置及目标环境验收记录。

## 3. 阶段 1：数据范围权限

1A 的规则与当前入口矩阵见[数据中心范围授权](DATA-SCOPE.zh-CN.md)。已提供授权管理界面、核心资源隔离和在途请求撤销协调。局部报表与批量业务操作已追加适配，先完善现有中心授权的可用入口。局部资产导入、共享型号导出与资产时间线已追加适配；目录类导入继续采用共享主数据的全局写入规则。时间线保留受限事件，但不公开越界或证据不足的明细。1B 已落实独立部门归属及交集授权，旧数据仍待人工确认；现已提供基础规则与最多 20 条附加规则，完整条件内取交集、规则间取并集；读写组合也不交叉扩张。并发读请求以一致快照组装响应。

**建议拆成三批**

| 批次 | 范围 | 关键设计 |
| --- | --- | --- |
| 1A | 数据中心范围 | 保留现有功能权限；新增独立的读写范围授权，先覆盖资产、设施、库存、盘点和相关附件 |
| 1B | 部门范围 | 为资产建立明确的归属部门，人员使用其部门关系；不把当前使用人的部门自动当作资产归属部门 |
| 1C | 全入口统一与管理界面 | 覆盖导出、报表、搜索、批量操作、导入、历史、幂等重放及后续作业；提供授权维护和权限解释 |

**规则先定清楚，再实现**

- 功能能力与数据范围分别判断，操作必须同时满足两者。读范围和写范围独立配置，只有明确的管理授权才能访问全局。
- 同一授权规则内中心与部门取交集，多条完整规则取并集；写授权包含完整写组合的读取，选中部门不隐含下级。
- 未分配数据中心或归属部门的资产不能因字段为空而自动获得全局访问；先由全局管理员处理，或使用明确的“待归属”授权范围。
- 资产迁移、机房改挂、备件调拨必须同时校验当前范围和目标范围。关联选择项也需要过滤，不能只限制最终列表。
- 历史、归档和附件继承关联业务对象的授权规则；跨范围流水的可见性及审计展示方式形成明确矩阵。
- 保留现有备件数量与安全库存的全局口径，位置筛选仍只决定返回哪些备件。缺少全局统计授权时不展示全局指标；若需要范围内数量，增加独立字段及标签，不把 `total_quantity` 改成范围内合计，也不把无权读取显示成零库存。
- 全局字典、许可及其他共有资料逐类确定授权方式，不把中心范围过滤机械地套到所有表。盘点任务与汇总明确部分可见时的处理和完成权限。
- 幂等重放、作业执行和结果下载重新校验当前权限，撤销授权后不能通过旧结果继续取数。
- 网页、API、Admin 和服务器命令分别明确授权边界。Admin 继续只读；具有数据库访问权的运维账号通过独立运维流程管理。

旧数据先生成归属预览与异常清单，再人工确认并回填；不得自动猜测资产归属或为普通用户默认开放全局。公司级隔离暂不叠加进首批，若确认有多公司需求，再设计对应组织模型。

**完成标准**：中心 A 的管理员不能读取或修改中心 B 的业务数据，也不能通过数量统计、导出、关联选择或附件取得范围外资料；只拥有来源范围的人不能向未经授权的目标调拨。旧用户与未归属数据有明确处理结果。

**交付物**：权限矩阵、数据范围模型与迁移、公共授权模块、授权管理界面、旧数据归属方案。

## 4. 阶段 2：写入边界与后台作业

### 2A. 补齐写入协议（已实施）

已为账号及本人资料、系统/品牌/LDAP 设置、故障、维修、盘点任务/记录、附件普通编辑增加 revision / If-Match。完整表单在规范锁顺序内检查版本；账号批量启停比较逐条读取版本。专用状态动作保留当前状态和观察校验，库存与维修用件沿用事务性幂等。冲突保留前端输入，不自动覆盖。迁移 0013 仅增加版本字段，详细入口与兼容要求见[写入一致性说明](WRITE-CONSISTENCY.zh-CN.md)。

涉及密码、密钥或凭证的结果，不得将明文放进可重放响应或审计。保持已确认的时间规则：报障和维修不得早于故障发生，完成不得早于开始，允许先维修后补报障。

### 2B. 按业务域收拢写入

优先收拢库存、盘点、维修和资产生命周期，再处理身份与主数据。每个业务动作由明确入口维护事务、锁顺序、授权和审计；视图负责接收请求，序列化器负责字段处理。前端按相同业务域拆分大文件，保持现有 API 路径和成功响应兼容。

拆分与真实行为修复一起推进，每批只处理一个业务域，避免先大规模搬文件再寻找约束。

库存批次已实施：初始库存、普通流水和维修领料的规则、事务、授权、审计及幂等提交统一到库存模块；修复领料与设施变更锁顺序，并检查重放时的库存功能能力。前端拆出库存操作模块，目录表单保留打开时版本。入口与运行约束见[库存领域写入](STOCK-WRITES.zh-CN.md)。本批没有新增迁移。

盘点批次已实施：任务、观察、纠正、批量及完成/重开的规则、事务和审计统一到盘点模块；任务写入在位置及清单资产锁后复核完整授权。直接位置的正常确认补齐中心启用校验，前端完成确认期间切换任务不会向另一任务提交。冻结快照、逐条批量结果和既有协议保留，详见[盘点领域写入](INVENTORY-WRITES.zh-CN.md)。本批没有新增迁移。

维修生命周期批次已实施：领域写入、时间及历史规则、状态同步和审计收拢到独立模块；修复派生故障更新时间未同步、前端旧请求关闭新草稿，以及编辑等待锁期间维修被删除返回服务器异常的问题。范围复核和派生状态与审计保持同一事务，领料锁顺序与库存模块一致。说明见[故障与维修领域写入](REPAIR-WRITES.zh-CN.md)。本批无新增迁移，不引入多轮维修历史；接下来处理资产生命周期及身份/主数据。

资产生命周期批次已实施：字段规则、配置存储、单资产事务及逐条批量操作分别收拢；普通编辑与责任、报废、归档/恢复使用领域写入和审计。修复直接中心新建/迁移在等待期间被停用仍能成功的问题，以及前端迟到保存/确认污染新草稿和批量责任响应清除新增选择的问题。身份与历史保持，未新增迁移。详见[资产领域写入](ASSET-WRITES.zh-CN.md)。接下来收拢身份及共有主数据，然后进入 2C。

身份及共有主数据批次已实施：账号、角色保护、密码、资料及范围替换收拢到身份模块；共有目录、字段集成员、引用保护及审计收拢到主数据模块。修复账号编辑等待期间被删、并发账号抢占人员、字典确认切换导致错误目标，以及账号/目录迟到响应影响新草稿的问题。部门层级、字段/选项和字段集成员使用明确锁顺序，保留既有版本和名称审计快照。无新增迁移，详见[身份与共有主数据写入](IDENTITY-REFERENCE-WRITES.zh-CN.md)。2B 本地批次完成，下一批进入 2C 的持久后台作业。

### 2C. 持久后台作业（本地实施）

已增加持久作业表、独立 worker、本人作业面板和结果下载，网页四类导入及九类导出改为后台提交，摘要定时器只登记作业。整份导入与作业完成同事务提交，进程锁防止活 worker 被接管，权限变化和维护阻断执行；输入/输出纳入备份媒体清单，恢复暂停当日自动摘要。迁移 0014，详见[持久后台作业](BACKGROUND-JOBS.zh-CN.md)。旧同步 API 保留有界兼容；逐行进度、运行中取消和多节点调度不在第一版范围。

先迁移大导入、导出及通知，再承接后续采集和对账。第一版使用持久作业记录和独立 worker，具体调度实现根据单机规模确定，不先绑定复杂消息平台。

作业保存提交者、输入引用、状态、进度、执行次数、检查点、失败原因和结果。业务提交与待执行作业的登记具有一致性保证；进程退出后能识别未完成任务。定义每类作业的提交粒度、重试和取消语义，重试复用操作身份。

worker、定时作业及文件清理都必须参与现有维护屏障，在数据库事务和提交后的文件回调结束前持共享访问锁。备份和恢复继续使用服务器 CLI 与独占维护窗口，网页保留现有说明、列表和下载行为。

**完成标准**：长任务不占用 HTTP 请求等待；执行状态可查询；重启、重试或取消不会重复扣库、重复导入或留下无归属结果；授权撤销及维护窗口同样约束后台执行。

**交付物**：写入入口清单、逐域模块、持久作业模型与迁移、worker、进度与结果页面、运行与故障恢复说明。

**完成标准**：重开维修和续约后仍能查询完整旧事实；同一用件只对应一次库存变化；审批与执行可分别追溯；资产归档后单据和证据继续可读。

**交付物**：业务模型、迁移与兼容方案、维修/合同时间线、必要审批界面及历史留存规则。

## 6. 阶段 4：自动发现、对账与集成

### 4A. 一个来源的采集与身份匹配

根据现有环境选择一个来源作为首个连接器，例如虚拟化平台或现有设备清单接口。先建立采集暂存记录、来源标识、外部 ID、采集时间、最后见到时间和标准化规则，再连接正式台账。

同一来源重复采集不产生重复资产。跨来源匹配依据稳定身份和人工确认；空序列号、克隆设备、重装或重复地址进入差异队列。设置字段来源优先级和人工锁定规则，采集不能直接覆盖已确认字段。

### 4B. 差异处理与运行闭环

提供新增、变更、冲突及长期未见的差异列表，支持确认、拒绝与纠错。未被发现仅产生待核查事项，不自动认定报废。采集任务具有失败提示、重试及权限约束。

### 4C. 按收益增加外部集成

HR 优先人员状态与部门同步，保留离职资产待回收流程；ERP 优先采购、订单和供应商事实；监控优先设备身份关联与故障候选。明确各系统的权威字段、同步方向和删除规则，避免双向循环写入。

**完成标准**：每条采集事实可追溯来源；重复采集不重复创建；冲突不会静默覆盖台账；来源离线或权限变化不会破坏已确认资料。

**交付物**：一个可用连接器、采集模型、匹配与差异处理模块、来源管理界面、后续连接器接口规范。

## 7. 阶段 5：成熟 ITAM 能力

以下分成独立能力批次，按用户需求排序，不要求同时建设。

| 能力 | 最小实施范围 | 依赖及完成标准 |
| --- | --- | --- |
| 软件授权对账 | 产品/版本、授权权益和证据、安装/消费事实、设备或用户分配、回收及可解释对账 | 依赖阶段 3 的采购事实和阶段 4 的可靠消费来源；授权分配约束与实际超用事实分开处理 |
| CMDB 关系 | 先建立实际需要的宿主机/虚拟机及资产/应用关系，再按需扩展接口和网络空间 | 关系有来源、有效性和纠错入口；网络空间扩展不得直接放松现有全局 IP 唯一约束 |
| 成本与更新规划 | 采购、维修、维保成本事实，成本中心、TCO、闲置及更新规划 | 依赖完整成本来源和稳定统计口径；报表数值可以下钻到事实记录 |

如果后续确定转向全企业终端管理，应提前提高 HR 集成、终端采集、软件授权对账和离职回收的优先级；如果继续聚焦机房运营，优先发现、设施/网络关系、合同与维修成本。

**交付物**：按所选能力分别交付领域模型、来源与计量规则、对账/关系/分析界面、迁移方案及运行说明。

## 8. 条件阶段：多节点运行

当前单机、多 Gunicorn worker 维护机制继续保留。只有在明确高可用、扩容或多节点部署需求后启动本阶段。

设计跨节点维护准入与排空、共享或不可变媒体存储、worker 租约与接管，以及数据库恢复期间的统一停写。单机文件锁不能直接沿用为跨节点协调；失去协调能力时应阻止新的业务写入。重新验证恢复与作业接管时的一致性，再开放多节点部署。

**交付物**：部署拓扑、协调方案、存储与恢复设计、切换与故障接管说明。

## 9. 开放条件与批次交付

受控单中心试点至少完成阶段 0，并明确试点用户的数据访问范围。向多部门或多中心开放前必须完成阶段 1。大量导入/导出或持续采集依赖阶段 2；采购、维修及处置的正式审批使用依赖阶段 3。阶段 4、5 按业务需求逐步启用。

每批交付代码、迁移、接口/行为变化和操作说明，分别提交，并更新审查报告中的当前状态。用例、脚本、执行结果和验收记录放在 `ITAM-private`。验证安排见该目录的 `docs/NEXT-STAGES-VERIFICATION-2026-10-09.md`。

正式部署另按已经约定的发布流程执行。日期和人力尚未确定，本计划不承诺日历工期；确定人员、目标环境和业务规则后，逐批估算并排期。

**下一批进入阶段 3A 的多轮维修历史**；阶段 2A、2B、2C 本地实现完成，仍需目标服务器上的 worker、目录权限、容量和升级验收。阶段 1 的多规则授权已完成；同一条规则选择多个中心和部门仍开放该规则全部交集组合，需要按组合隔离时分别建规则。旧资产归属与普通账号授权需人工确认后才能开放业务。 阶段 0 还需在实际目标服务器完成安装、运行及恢复验收；本地锁定环境通过不能替代该步骤。
